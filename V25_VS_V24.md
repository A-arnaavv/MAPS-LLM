# MAPS-LLM v2.5 vs frozen v2.4 paired evaluation

Purpose: test whether v2.5's endogenous regime-aware safety improves realized
operational outcomes relative to the frozen v2.4 scheduler.

## Design

- 4 scenarios:
  - balanced
  - strict_sla
  - bursty_multiuser
  - model_degradation
- 2 scheduler versions:
  - V2_4
  - V2_5
- 20 paired seeds
- 500 tasks per run
- 160 runs total

Both versions receive byte-identical workloads and stochastic traces for each
scenario/seed pair.

## Run the paired experiment

```bash
PYTHONPATH=. python3 experiments/run_v25_vs_v24.py \
  --tasks 500 \
  --seeds 20 \
  --outdir results/v25_vs_v24
```

Expected run count:

    4 × 2 × 20 = 160

## Statistical analysis

```bash
PYTHONPATH=. python3 experiments/statistics_v25_vs_v24.py \
  --csv results/v25_vs_v24/v25_vs_v24_by_seed.csv \
  --outdir results/v25_vs_v24_stats
```

For each scenario and metric the analysis computes:

- paired Wilcoxon signed-rank test
- Holm correction across metrics within that scenario
- 20,000 paired-bootstrap 95% CI
- paired Cohen's dz
- paired rank-biserial correlation

Positive advantage means v2.5 is better.

## Decision criterion

Primary target scenarios:
- bursty_multiuser
- model_degradation

Primary operational outcomes:
- P95 latency
- SLA violation rate

Guardrail outcomes:
- quality
- worst-user utility
- cost/task

The goal is not universal superiority. v2.5 succeeds if it materially improves
operational risk under adverse regimes without an unacceptable collapse in
quality or worst-user service.
